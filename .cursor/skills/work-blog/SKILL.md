# Skill: work-blog

세션에서 한 일을 **개발일지 연재 한 편**으로 고정한다. 채팅 요약·PR·커밋 메시지가 아니다.

출력 파일 = 사람용 글. 채팅 안내만 기존 caveman.

문체·구성 정본: [references/voice.md](references/voice.md). **본문 쓰기 전에 읽는다.**  
블로그: https://duplicated.tistory.com/ — 연재는 리그오브워치 개발일지. `#0`/`#1` 에세이는 말투 샘플이 아니다.

## 언제

사용자가 작업물을 **밖으로 가져가려 할 때**. 구현 직후 「정리해」만 있어도 이 스킬. 구현 요청과 섞이면 **구현 먼저**, 글은 끝에.

## 쓰지 말 것

- `README.md`·`Docs/` — 사용자 명시 없이
- git 커밋 — `.result/`는 gitignore. 스테이징 금지
- 검증 안 한 PIE/수치를 된 것처럼
- 에이전트 내부어(RULE-0x, caveman, MCP requestId) 본문에 풀기
- caveman 문장 패턴을 **본문**에 넣기 — 조각문, 「그건 X」, 「대략:」, 식별자만 이어 붙인 문장
- 마크다운 `---` 구분선 (티스토리 가로줄). 절은 `##`만 (제목 `#` 하나)
- 질문형 절 제목 (`Lyra란 무엇인가`, `1인칭 카메라는 어떻게 붙이나`)
- 표·mermaid로 프레임워크 수업. 연재는 요구사항 목록·구현 소절
- 「스폰까지 확인」「에디터에서 한 번 더」처럼 작성자 검증 로그를 본문에 넣기
- 이번 편에서 안 한 기능 목록 (`다루지 않는다`, 무기·히어로 예고, `## 다음 글`). 요구사항은 한 일만.
- `## 어려웠던 점`. 막힌 이유는 구현 소절에 이어서 적는다.

## 독자

글에 없는 프로젝트 내부 상황을 **모른다**. 언리얼 일반 지식은 있어도 이 저장소 핀 이름은 모른다.

- 현상·선택을 한국어로 먼저. 식별자는 구현을 걸을 때만
- 쓸 식별자는 코드와 철자 동일. 쓰이지 않으면 생략
- 코드 블록은 핵심 함수·클래스만. 많으면 Git을 가리킨다

## 소스

1. [references/voice.md](references/voice.md) + (여유 있으면) 정본 연재 1편
2. 사용자 첨부 플랜·열린 `.result` 초고 — 있으면 뼈대 우선, **말투는 정본**
3. 이번 대화에서 한 일
4. `git diff` / 관련 소스 — 경로·API는 파일에서 재확인

사용자 `.result/Blog.md` 등 초고는 덮어쓰지 않음. 이미 올린 `#0`/`#1`을 에세이 스타일로 다시 쓰지 않음.

## 출력

경로: `.result/<slug>.md`

- `slug`: 소문자 kebab. 사용자가 파일명·제목을 주면 그걸 우선
- 채팅: 경로 + 한 줄. 본문 전체를 채팅에 붙이지 않음

### 이미지·영상 자리

넣을 사진·GIF·영상·블루프린트 샷은 본문에 **백틱으로 감싼** 한 줄로 남긴다. 작성자가 찍어 올린다. URL·`![alt](url)`·파일 첫 줄 촬영 메모는 쓰지 않는다.

````
`[B_Manny 컴포넌트 트리 MeshComponent·FirstPersonMesh 이미지 추가]`
`[1인칭 걷기·시선 영상 추가]`
````

- 백틱 안: `[` + 어디(에셋·화면) + 무엇 + `이미지 추가` 또는 `영상 추가` + `]`. 에디터/PIE에서 그 컷을 찍을 수 있게.
- C++는 코드 블록. 그래프·디테일·플레이 컷은 이 형식.
- 없어도 글이 되면 넣지 않음. 입문(`#0`)은 기본으로 없음.

## 구성

권장 뼈대는 **사용자 아웃라인이 없을 때**. 절은 있는 내용만. 상세·예문은 voice.md.

1. 제목 `[언리얼5] 멀티플레이 FPS #<N> <주제>`
2. `github :` 저장소 URL. 이으면 `이전 글 :` URL
3. `## 요구사항 확인` — 이전 편 한 줄 + 이번에 한 일 번호 목록
4. 개념이 필요하면 짧은 `##` 하나 (함수 vs 변수 수준)
5. `## 구현` — 요구사항과 같은 순 소절. 에디터·코드에서 한 일
6. `## 완성된 모습` — 있을 때만

입문 편은 목표 나열로 바꿔도 된다. 질문형 제목은 입문에도 쓰지 않는다.

## 문체

한국어 한다체. 개발일지. 자랑조·마케팅 금지.

- `이전글에서는` / `이번 글에서는 … 할 것이다` 로 편을 잇는다
- 1인칭 허용 (`나는`, `필요를 느꼈다`)
- 트레이드오프·우회는 숨기지 않음. 목록으로 써도 된다. **이번에 손댄 구현**만.
- 목차·인사 없음

## 사실 게이트

- 우회·미완은 **이번에 한 구현** 안에서만. 에디터 핀 우회는 한두 문장이면 충분
- 아직 안 만든 시스템을 본문에 올리지 않음. 「확인했다」는 독자가 화면에서 볼 결과만. 촬영 예정이면 `` `[… 이미지/영상 추가]` ``만
- C++/에셋 추정 금지. 코드와 글이 다르면 코드가 맞음. 글에는 그 사실을 풀어 씀
