# UE5NetworkFps 기획서

> 상태: 초안 (2026-10-18). 수치는 모두 초기값이며 DataAsset에서 조정한다.

## 1. 개요
| 항목 | 내용 |
|---|---|
| 제목 | UE5NetworkFps (가제) |
| 장르 | 1인칭 5 vs 5 히어로 슈터, 화물 운송 |
| 성격 | 세계관 없는 기술 데모 |
| 플랫폼 | PC (Steam) |
| 엔진 | Unreal Engine 5.8.3 (5.7에서 업그레이드), Lyra 기반 |
| 분량 | 그레이박스 맵 1개 + 히어로 3명 + 봇 |
| 기간 | 8주, 주 15시간 (총 약 120시간) |
| 목적 | 포트폴리오 |

**핵심 목표**: 오버워치식 히어로 3명과 화물 운송 한 판을 끝까지 돌리는 것. 그 위에서 **서버 권한 판정과 랙 보상, GAS 예측, 데디케이티드 서버, Steam 세션**을 동작하는 형태로 보여준다.

## 2. 핵심 게임 루프
```
세션 찾기/만들기 → 로비 → 히어로 선택 → 전투·화물 밀기/막기 → 승패 → 로비
                                  ↑            │
                                  └─ 사망 ─────┘ (리스폰 대기 후 스폰 방에서 재선택 가능)
```

## 3. 매치 규칙: 화물 운송 (단판 공격/수비)
| 항목 | 내용 |
|---|---|
| 인원 | 5 vs 5, 빈자리는 봇이 채움 |
| 진행 | 공격팀이 화물을 경로 끝까지 밀면 승리, 제한 시간이 끝나면 수비팀 승리 |
| 체크포인트 | 경로에 3개 (A, B, 도착). 도달하면 제한 시간 추가, 공격팀 스폰 지점이 앞으로 이동 |
| 화물 속도 | 근처 공격팀 인원 1/2/3명 이상일 때 속도 75% / 87.5% / 100% |
| 경합 | 수비팀이 화물 근처에 있으면 멈춤 |
| 후퇴 | 공격팀이 일정 시간 화물을 떠나 있으면 마지막 체크포인트 쪽으로 천천히 후퇴 |
| 연장전 | 시간이 끝나도 공격팀이 화물에 붙어 있으면 연장. 비우면 연장 게이지가 줄어들어 0이 되면 종료 |
| 준비 시간 | 시작 전 대기 (공격팀 스폰 문 닫힘, 수비팀 이동 가능) |
| 리스폰 | 사망 후 대기 시간 뒤 팀 스폰 지점에서 부활 |
| 히어로 교체 | 스폰 방 안에서만 가능 |

수치(제한 시간, 연장 시간, 후퇴 대기, 리스폰 대기, 화물 판정 반경)는 모드 설정 DataAsset 한 곳에 모은다.

## 4. 히어로 공통
| 항목 | 상세 |
|---|---|
| 섀시 | 모든 히어로가 `Heroes/Shared/BP_FpsHero`를 공유. 히어로별 차이는 HeroData, AbilitySet, 무기, 외형으로만 |
| 생명력 | 체력 / 방어구(받는 피해 일부 감소) / 보호막(재생) 3종을 GAS Attribute로 |
| 이동 | 걷기, 점프, 앉기 없음 (오버워치 기준). 히어로별 이동 속도 배율 |
| 시점 | 1인칭 (`CM_FirstPerson`). 다른 플레이어에게는 3인칭 메시 |
| 스킬 | 슬롯: 주무기, 보조 사격, 스킬 1 (Shift), 스킬 2 (E), 궁극기 (Q) |
| 궁극기 게이지 | 피해·치유량과 시간 경과로 충전, 100%에서 사용 가능. 충전 계수는 히어로별 데이터 |
| 치유 | 피해를 받은 뒤 일정 시간 지나면 자동 회복 (선택) |

## 5. 히어로
오버워치 원본 스킬을 그대로 재현한다. 이름은 내부 코드네임으로만 쓰고, 공개할 때는 이름과 외형을 바꾼다 (13장).

### 5-1. Soldier (공격)
| 슬롯 | 스킬 | 내용 |
|---|---|---|
| 주무기 | 중펄스 소총 | 연사 히트스캔, 탄창식, 거리별 피해 감소, 탄퍼짐 증가 |
| 보조 | 나선 로켓 | 투사체 3발, 범위 피해, 쿨타임 |
| Shift | 질주 | 앞으로 달리는 동안 이동 속도 증가, 사격 불가 |
| E | 생체장 | 설치형 장판, 범위 안 아군 지속 치유 |
| Q | 전술 조준경 | 일정 시간 시야 안의 적에게 자동 조준 |

### 5-2. Reinhardt (돌격)
| 슬롯 | 스킬 | 내용 |
|---|---|---|
| 주무기 | 로켓 해머 | 근접 휘두르기, 부채꼴 범위 다중 타격 |
| 보조 | 방벽 방패 | 앞에 내구도 있는 방벽 생성. 투사체와 히트스캔을 막음, 내구도 재생 |
| Shift | 돌진 | 직진 돌진, 처음 부딪힌 적을 잡고 벽에 박으면 큰 피해 |
| E | 화염 강타 | 관통 투사체, 충전 2회 |
| Q | 대지 분쇄 | 앞쪽 지면 충격파, 맞은 적 넘어뜨림(기절) |

### 5-3. Ana (지원)
| 슬롯 | 스킬 | 내용 |
|---|---|---|
| 주무기 | 생체 소총 | 적에게는 피해, 아군에게는 치유. 비조준은 투사체, 조준 시 히트스캔 |
| 보조 | 조준 | 확대, 이동 속도 감소 |
| Shift | 수면총 | 맞은 적을 재움, 피해를 받으면 깸 |
| E | 생체 수류탄 | 범위 안 아군 치유·받는 치유 증가, 적 피해·치유 차단 |
| Q | 나노 강화제 | 아군 1명 치유 + 주는 피해 증가 + 받는 피해 감소 |

**초기 수치**는 오버워치 2의 공개 수치를 참고해 HeroData와 GameplayEffect에 넣는다. 오버워치는 패치마다 수치가 바뀌므로 문서에 숫자를 고정하지 않고 데이터 에셋을 기준으로 한다.

## 6. 봇
| 항목 | 내용 |
|---|---|
| 역할 | 빈자리 채우기, 혼자 테스트·영상 촬영 |
| 히어로 | 무작위 |
| 행동 | 공격팀은 화물로 이동해 붙어 있기, 수비팀은 화물 앞을 막기. 보이는 적에게 주무기 사격 |
| 스킬 | 사용하지 않음 (추가 요소) |
| 구현 | Lyra 봇(`LyraBotCreationComponent`) 확장. 목표 지점만 화물 기준으로 바꿈 |

## 7. 맵 (그레이박스)
- 새 맵을 그레이박스로 만든다. 에셋은 Lyra 기본 메시·머티리얼만 쓴다.
- 구성: 공격팀 스폰 → 구간 1 (넓은 광장) → 체크포인트 A → 구간 2 (좁은 골목, 고지대) → 체크포인트 B → 구간 3 (수비팀 스폰 앞) → 도착
- 화물 경로는 스플라인으로 정의한다. 각 구간에 엄폐물, 우회로, 고지대(Ana 시야)를 둔다.
- 팀마다 스폰 방(히어로 교체 구역)을 두고, 공격팀 스폰은 체크포인트마다 앞으로 옮긴다.

## 8. 네트워크 설계
### 8-1. 서버 권한 히트 판정 + 랙 보상
| 항목 | 방식 |
|---|---|
| 권한 | 피해·치유·사망은 서버만 결정. 클라이언트는 연출(탄흔, 피격 표시)만 예측 |
| 히트스캔 | 클라이언트가 사격 시점과 조준 정보를 보냄 → 서버가 해당 시점으로 적 히트박스를 되감아 다시 판정 |
| 되감기 | 서버가 캐릭터별 히트박스 위치를 최근 일정 시간 동안 링 버퍼로 기록, 보간해 과거 위치 복원 |
| 보상 한도 | 되감기 최대 시간을 설정값으로 둠. 넘으면 보상하지 않음 |
| 검증 | 사거리, 연사 속도, 탄약, 시야 가림을 서버에서 확인. 어긋나면 무효 |
| 투사체 | 클라이언트는 즉시 가짜 투사체를 보여주고, 서버가 진짜를 생성해 판정. 도착 후 보정 |
| 근접 | Reinhardt 해머도 같은 되감기를 거쳐 서버에서 부채꼴 판정 |

### 8-2. GAS 예측
- 스킬 사용, 쿨타임, 탄약, 충전 횟수는 GAS 예측으로 즉시 반응하고, 서버가 거부하면 되돌린다.
- 이동형 스킬(질주, 돌진)은 Character Movement와 맞물려 끊김이 없게 만든다.
- 궁극기 게이지는 서버 권한, 클라이언트에는 복제만.

### 8-3. 데디케이티드 서버
- 개발 중에는 Listen 서버로 테스트한다.
- 마지막 주차에 5.8 소스 엔진을 빌드해 `LyraServer` 타깃으로 서버를 패키징한다. 설치판 엔진(`InstalledBuild`)은 Server 타깃을 빌드할 수 없다.
- 서버는 실행 인자로 맵과 모드를 받는다.

### 8-4. Steam 세션
- Lyra의 CommonUser·CommonSession을 써서 세션 만들기, 검색, 참가를 한다.
- 테스트는 Steam 테스트 AppID로 한다. AppID는 설정 파일에서 읽는다.
- 로비에서 인원이 모자라면 봇으로 채우고 시작한다.

### 8-5. 네트워크 품질 확인
- 지연과 패킷 손실을 넣고(`Net PktLag`, `Net PktLoss`) 히트 판정, 스킬 예측, 화물 진행이 맞는지 확인한다.
- 대역폭이 큰 액터(화물, 방벽, 장판)는 복제 빈도와 관련성을 정한다. ReplicationGraph 사용.

## 9. UI
- HUD: 체력/방어구/보호막 바, 탄약, 스킬 쿨타임, 궁극기 게이지, 십자선, 피격 표시, 처치 알림
- 화물 진행 바: 진행률, 체크포인트, 경합 상태, 남은 시간, 연장전 표시
- 히어로 선택 화면, 스코어보드
- 메인 메뉴: 세션 만들기/찾기, 설정 (Lyra UI 재사용)
- 승리/패배 화면

## 10. 이펙트와 사운드
- Lyra의 Niagara 이펙트와 사운드를 재사용하고, 히어로 스킬은 색과 모양으로 구분한다.
- 발생 시점은 GameplayCue로 연결해 네트워크로 연출을 퍼뜨린다.

## 11. 기술 설계
| 항목 | 방식 |
|---|---|
| 게임 구조 | Lyra Experience + Game Feature (`FpsCore`, `FpsMaps`). 모드는 새 Experience |
| 히어로 | 공통 섀시 + HeroData (PawnData, AbilitySet, 무기, 외형) |
| 스킬 | GAS (GameplayAbility, GameplayEffect, GameplayCue) |
| 수치 | DataAsset·DataTable 한 곳에 모음 |
| 입력 | Enhanced Input (Lyra InputConfig) |
| 화물 | 서버가 움직이는 액터, 스플라인 경로, 진행률만 복제하고 위치는 클라이언트가 경로에서 계산 |
| 모드 규칙 | GameState 컴포넌트 (Lyra 방식)로 시간, 체크포인트, 연장전 관리 |
| 랙 보상 | 서버 히트박스 기록 컴포넌트 + 되감기 판정 |
| 봇 | Lyra 봇 + 화물 목표 |
| 세션 | CommonUser / CommonSession + OnlineSubsystemSteam |

## 12. 검증
| 종류 | 대상 |
|---|---|
| Automation (단위) | 피해 계산, 방어구 감소, 궁극기 충전, 화물 속도 계산, 되감기 보간 |
| Functional Test (멀티 PIE) | 서버-클라이언트 2~3개로 사격 판정, 스킬 쿨타임 예측, 방벽 막기, 화물 이동·경합·체크포인트·승패 |
| 지연 시나리오 | 가짜 지연을 넣은 상태에서 되감기 판정이 맞는지 |
| Gauntlet (추가 요소) | 데디 서버 + 클라이언트 자동 실행 |
