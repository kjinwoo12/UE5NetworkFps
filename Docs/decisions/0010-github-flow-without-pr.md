# 0010. 브랜치는 GitHub Flow를 따르되, PR 없이 main에 머지한다

- 상태: 채택
- 날짜: 2026-10-27

## 배경

지금까지는 main에 바로 커밋했다. 기능 여러 개가 동시에 진행되면 중간 상태가 main에 섞이고, 한 기능을 되돌리기도 어려웠다. 반면 지금은 혼자 개발하는 단계라 PR 리뷰 절차는 비용에 비해 얻는 게 적다.

## 결정

- 새 기능이나 작업마다 main에서 브랜치를 만든다. 이름은 `feature/<이름>`, 문서는 `docs/<이름>`처럼 종류를 앞에 붙인다.
- 작업이 끝나면 브랜치를 main에 머지하고 푸시한다.
- PR은 만들지 않는다.
- main은 항상 빌드되고 회귀 검사를 통과하는 상태로 둔다.

## 대안

- **main 직접 커밋:** 중간 상태가 main에 섞인다.
- **GitHub Flow + PR:** 리뷰어가 생기면 맞지만, 혼자일 때는 절차만 늘어난다.
- **Git Flow(develop·release 브랜치):** 릴리스 주기가 없는 지금 규모에는 과하다.

## 결과

- 기능 단위로 기록이 나뉘고, 되돌리기 쉬워진다.
- 리뷰 기록이 남지 않으므로 커밋 메시지와 이 ADR이 결정의 기록이 된다.
- 함께 개발할 사람이 생기면 PR을 다시 검토한다.
