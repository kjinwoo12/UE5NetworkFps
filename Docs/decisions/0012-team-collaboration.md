# 0012. 팀 작업은 Fork와 git flow로 나누고, GitHub Issues·Projects·마일스톤으로 추적한다

- 상태: 채택
- 날짜: 2026-10-28

## 배경

팀원 합류에 대비해 협업 방식을 미리 정한다. 0010(GitHub Flow, PR 없음)은 메인테이너 혼자 작업할 때의 방식이라 팀 작업에는 쓰지 않는다.

## 결정

- 팀원끼리 주 1회 스크럼을 하고 Done, Todo, Issue를 공유한다. 기록은 GitHub Discussions에 남긴다. 요일과 시간은 팀원이 모이면 정한다.
- 의사 결정과 작업은 GitHub Issues, Projects 칸반 보드, 마일스톤으로 추적한다. 이슈 템플릿은 "작업"과 "의사 결정" 두 가지를 둔다. 로드맵은 마일스톤(M0~M5)으로 관리한다.
- GitHub 조직을 만들어 팀 작업물을 조직 레포로 관리한다. 지금 레포는 팀원이 모이면 조직으로 옮긴다.
- 팀원은 팀 레포를 Fork해 개인 레포에서 작업한다.
- 브랜치는 git flow(`main`, `develop`, `feature/*`, `release/*`, `hotfix/*`)로 관리한다. 팀원은 Fork 안의 브랜치를 자유롭게 쓰고, 팀 레포의 해당 `feature/*`로 PR을 올린다. `feature/*`를 `develop`에 합치는 것은 메인테이너가 한다.

## 대안

- **팀원 PR을 `develop`으로 바로 받기:** 여러 명이 한 기능을 할 때 `develop`이 자주 흔들려서 고르지 않았다.

## 결과

- 개인 작업과 팀 레포가 분리되고, 팀 레포에는 PR로만 들어온다.
- 기능마다 팀 레포에 `feature/*` 브랜치를 먼저 만들어 둬야 한다.
- 개인 계정에 만든 Projects 보드는 레포를 조직으로 옮길 때 따라가지 않을 수 있다.
- 팀원용 절차는 위키 온보딩 가이드 5장에 적는다.
