# 0004. 풀바디 1인칭(true first person)으로 전환한다

- 상태: 채택 (이전 방식은 `bTrueFirstPerson=False` 레거시 모드로 남김)
- 날짜: 2026-10-19

## 배경

처음 방식은 카메라를 캡슐 눈높이에 두고, 1인칭 컨트롤 릭이 머리를 카메라에 붙이고 어깨를 시점 피치만큼 돌렸다. 아래를 보면 총이 몸통을 통과해서 상체를 뒤로 밀었는데(`LookDownBodyBack` 40cm), 두 문제를 동시에 없앨 수 없었다.

- 골반까지 밀면 발이 그림자보다 27cm 뒤에 있었다.
- 상체만 밀면 아래 85°에서 총이 골반을 통과했다.

한 증상을 고치면 다른 증상이 되살아나는 일이 반복됐다.

## 결정

본인 화면의 몸은 3인칭 애니메이션 포즈를 그대로 쓰고, 카메라를 애니메이션된 머리(눈)에 붙인다.

- 눈 위치 = `head` 뼈 + 시점 회전 × `EyeViewOffset`(앞 8, 위 10cm). 애님과 카메라가 같은 함수로 구한다.
- 아래를 보면 애니메이션이 머리를 앞으로 내밀므로 카메라도 앞으로 나가고, 총이 몸통 앞에 있다.
- 앉기·몸 기울기 같은 카메라 높이 변화도 애니메이션이 만든다.
- 코드는 팔만 다시 푼다(총 고정, 손 고정, 팔이 닿지 않으면 어깨·가슴 보정).
- 본인 화면에서만 머리를 숨긴다.

## 대안

- **분리 리그 유지(카메라 고정 + 상체 밀기):** 위 두 증상을 동시에 해결하지 못했다.
- **팔만 있는 뷰모델 메시:** 아래를 볼 때 다리가 안 보이고, 그림자와 몸이 따로 논다.

## 결과

- 발·골반이 그림자와 0cm 차이가 됐고, 아래를 보면 자기 다리와 발이 보인다.
- 카메라가 애니메이션 머리를 따라가므로 걸을 때 화면이 함께 움직인다. 팔·어깨 흔들림을 걸러내는 필터가 여러 개 필요했다(어깨 저역 통과, 가슴 이동, 팔꿈치 폴 필터).
- 1인칭 관련 변경은 회귀 검사 전체를 통과해야 끝난 것으로 본다([0009](0009-automation-regression-test.md)).
- 레거시 모드는 비교와 되돌리기용으로 남긴다.
- 자세한 구조: [FirstPersonRig.md](../FirstPersonRig.md) 3·6장.
