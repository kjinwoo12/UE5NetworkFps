# 0006. 로컬 1인칭 총은 이벤트로 갱신한다

- 상태: 채택
- 날짜: 2026-10-26

## 배경

본인 화면 전용 총(로컬 총)은 복제되는 무기 액터를 보고 만들고, 붙이고, 숨기고, 지운다. 처음에는 매 틱 무기 상태를 확인(폴링)했다. 할 일이 없는 틱에도 비용이 들고, 무엇이 갱신을 일으켰는지 알기 어려웠다. 클라이언트에서는 무기 액터 복제, 소켓 부착 복제, 빙의 순서가 매번 달라서 폴링 주기 사이에 총이 늦게 붙는 경우도 있었다.

## 결정

`UFpsFirstPersonWeaponComponent`는 폴링하지 않는다. 다음 이벤트가 오면 다음 틱에 한 번 동기화하고, 같은 틱에 온 요청은 합친다.

- 빙의·컨트롤러 변경
- 장비 추가·제거, 클라이언트의 무기 액터 복제(`ULyraEquipmentManagerComponent::OnEquipmentChanged`)
- 아직 안 붙은 무기 루트의 소켓 부착 복제(`TransformUpdated`, 붙으면 해제)
- 복제 무기 파괴(`OnEndPlay`)
- 코스메틱 교체, 1인칭 애님 인스턴스 재초기화
- 손 고정(그립 잠금)
- 에디터에서 설정 변경

이벤트가 없던 Lyra 장비 매니저에는 변경 알림(델리게이트)을 추가한다(`EquipItem`/`UnequipItem`, FastArray 복제, `OnRep_SpawnedActors`).

## 대안

- **매 틱 폴링 유지:** 단순하지만 낭비가 있고, 원인 추적이 어렵다.
- **타이머 폴링(주기 낮춤):** 비용은 줄지만 늦게 붙는 문제가 그대로다.

## 결과

- 평소에는 비용이 없고, 갱신 원인이 이벤트 목록으로 정리된다.
- Lyra 코어(장비 매니저·장비 인스턴스)에 작은 수정이 들어갔다. Lyra를 업데이트할 때 이 부분을 다시 확인해야 한다.
- 새 갱신 원인이 생기면 이벤트 목록에 추가해야 한다(빠뜨리면 총이 갱신되지 않음).
- 이벤트 표: [FirstPersonRig.md](../FirstPersonRig.md) 4.1.
